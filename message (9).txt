1. Project goal

Build a complete certificate platform for the YMCA Ethiopia Summer Program 2026.

The system has three connected responsibilities:

Certificate generation
Read the certified participant CSV files.
Generate an individual certificate for each certified course completion.
Use the supplied Certified.pdf as the certificate design/template.
Insert the participant's name.
Insert the completed course/field.
Generate a unique certificate ID.
Generate a unique QR code.
Produce the final PDF.
Participant certificate portal
Participants register and log in.
The system securely identifies/matches them to their own certified participant record.
Their certificates appear in their dashboard.
They can view/download only certificates belonging to them.
A participant must never be able to access another participant's certificate.
Public certificate verification
Every certificate has its own QR code.
Scanning the QR opens a public verification page.
The system checks the certificate ID against the database.
It displays whether the certificate is valid, revoked, or not found.
Verification must not require the certificate owner to log in.

8. Dynamic font fitting

Implement automatic font fitting.

For example:

font_size = 30

while text_width > max_width:
    font_size -= 1

But use proper PDF/font measurement rather than guessing based on character count.

The algorithm should calculate the actual rendered width using the selected font.

Example:

Digital Marketing

may fit at:

30px

while:

Personal Leadership and Development

may require:

26px

The text should remain centered.

9. Horizontal alignment

Dynamic fields should use explicit alignment rules.

Participant name:

CENTER

Course:

CENTER

Do not position text by assuming:

x = 400

and then drawing from that point.

Instead calculate:

text_width
available_width
center_x

and derive the actual starting X position.

Conceptually:

x = box_x + (box_width - text_width) / 2

This prevents different-length names from appearing visually off-center.

10. Vertical alignment

Do not assume that the PDF's text origin is visually equivalent to the center of the text.

Font ascent/descent must be taken into account.

The renderer should calculate the text's bounding box and place it vertically inside the designated field area.

This is particularly important for:

participant names
course names

because different fonts and font sizes have different ascent/descent metrics.

11. Font handling

Bundle the font with the application.

For example:

or another approved font that visually matches the template.

The same font must be used consistently in development and production.

19. Certificate ownership matching

This is one of the most important architectural decisions.

First inspect the actual CSV data and determine whether there is a reliable participant identifier such as:

email
participant ID
registration ID
other unique verified identifier

Use the strongest available identity information.

If email exists

Prefer:

CSV participant email
        ↓
verified account email
        ↓
participant
        ↓
certificate
If a unique participant ID exists

Prefer a controlled participant-ID claim process.

If only names exist

Do not pretend name matching is secure.

Implement a controlled claim/verification process, such as an administrator-issued claim code or another verification mechanism available to YMCA.

The implementation must inspect the actual data first and recommend the safest practical approach.

The most important design principle

There are three different concepts and Codex should keep them separate:

IDENTITY
Who is this person?

        ↓

OWNERSHIP
Which certificate belongs to this person?

        ↓

VERIFICATION
Is this certificate genuine?

A participant logging in proves their account identity.

The database determines which certificates they own.

The QR system determines whether a certificate is genuine.

Those must not be conflated.

And the certificate generator itself should be treated as an issuance service inside this architecture, not as the entire project.

The current visual bug with the course/field placement should also be treated as a real generation-engine bug, not a cosmetic issue: the final renderer needs bounded text layout, font measurement, automatic fitting, alignment, and post-generation validation so that all 446 certificates can be generated reliably without manually checking every PDF.
